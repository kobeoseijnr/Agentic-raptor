AG-Full: specification to verified design

Four agents share one blackboard (DesignState) and one hard budget (BudgetLedger, capped at the baseline's own SPICE/LLM spend). Each box below is one agent; the diagram shows what crosses the boundary between them, not just their names.

STAGE 1

Topology Generation

Input
Target spec: gain_target_db, ugbw_target_hz, phase_margin_target_deg, load_capacitance_pf
Does
  • Design-Planner: deterministically scores gm-demand (2π·UGBW·CL) and gain against measured per-stage-count TRAIN ceilings, classifies difficulty (easy/medium/hard), sets a soft stage-count / compensation prior — no LLM call
  • RAG: spec-conditioned retrieval of up to 6 past MEASURED records (successes and failures), capped at 2 per family for diversity — context only, never injected as a candidate itself
  • LLM Proposer: an SFT-tuned adapter (fine-tuned once offline, zero SPICE in that loop) generates from the plan- and evidence-conditioned prompt; a 14-rule structural validator canonicalises and dedupes the result
Output
StrategyPlan + validated candidate pool
STAGE 2

Topology Critic

Input
Candidate pool + StrategyPlan
Does
  • Checks the pool against the plan's own physics rules (stage coverage, compensation, hard-spec deep-comp) — deterministic, free
  • If unsatisfied, appends targeted feedback and requests another round from the same proposer (≤3 rounds, same LLM-attempt cap as the baseline)
  • Once satisfied, a hash-pinned linear contextual bandit (24 physical features) ranks the pool
Output
Top-2 candidates: one committed, one backup
STAGE 3

Optimization Supervisor

Input
Committed + backup candidates, shared BudgetLedger
Does
  • Probes both branches cheaply (3 SPICE calls each) with the real SAC sizer
  • Diagnoses each branch's trajectory (hopeless / stagnating / improving) and routes the remaining budget to the stronger one, banking the rest
  • Continues SAC sizing to verification; banked calls polish FoM after a pass without ever risking it
Output
Sized, verified design (pass/fail + measurements) and any leftover banked calls
STAGE 4

Recovery Agent

Input
A failed verification + whatever calls are banked
Does
  • Diagnoses the authoritative gain/PM/UGBW gap from the real measurement only
  • Fires at most once per run, and only if ≥4 calls are banked; otherwise reports NONE
  • Spends only banked calls — never a fresh charge against the cap — to re-size the untried backup branch
Output
A rescued passing design, or the original failure reported unchanged
